02 / THE BIG PICTURE

手機不是直接連到網際網路。

以 5G 為例，終端（UE）透過基地台進入無線接取網路（RAN），再經過核心網路（5GC）連到外部資料網路。核心網路也參與註冊、認證、移動性與連線管理。[1]

APPLICATION PROCESSOR

AP：應用程式所在的世界

在典型手機架構中，AP 執行 Android 與應用程式。App 的網路需求會經過作業系統與相關介面，與蜂巢式通訊子系統協作。

MODEM / BASEBAND

Modem：處理蜂巢式通訊

處理無線通訊協定與基頻相關工作，與射頻硬體協作。AP 與 Modem 的實體整合、作業系統和通道設計依平台而異。

此處是入門用的邏輯邊界。不是所有產品都採相同硬體切分；公開的 MediaTek T700 host driver 可作另一種平台案例。[4]

03 / PROTOCOL STACK

先認識每層的工作，不急著背縮寫。

點選協定層，看看它負責什麼。這是簡化的控制平面視角；NAS 在網路側終止於核心網路，RRC 則終止於 RAN，並不是所有層都與基地台完成對話。[2]

NON-ACCESS STRATUM

NAS · 與核心網路對話

處理註冊、移動性與 session 管理等控制程序。5G 中相關控制功能分布於 AMF、SMF 等核心網路功能。

讀 LOG 時的觀察方向

註冊進行到哪一步？是否收到拒絕與原因碼？

Control plane / 控制平面

建立與管理通訊所需的控制訊息，例如註冊、認證與無線連線設定。

User plane / 使用者平面

承載使用者資料，例如應用程式傳送的 IP 封包。5G NR 使用者平面還有 SDAP；上圖未展示完整使用者平面。

04 / CONNECTION JOURNEY

把名詞放進一次連線裡。

以首次進入 5G SA 網路為學習情境，下列是概念順序，不是完整時序圖。實際程序會受既有狀態、網路設定與錯誤處理影響。[2]

  1. 找到可用的無線網路

    搜尋、同步並取得系統資訊。先有可用的小區，才有後續接取的基礎。

  2. 建立無線控制連線

    透過接取程序與 RRC 連線建立，讓終端與網路交換控制訊息。

  3. 完成核心網路註冊與必要的安全程序

    NAS 參與註冊；網路依情況執行認證與安全設定。

  4. 建立資料連線並傳送資料

    透過 PDU session 與對應無線資源承載資料。「註冊成功」不等於所有應用程式都已能連上服務。

練習問題：App 連線失敗時，先區分無線接取、核心網路註冊、資料連線，以及 DNS／應用層問題。不要看到「無法上網」就假設一定是 Modem bug。
05 / YOUR WORK CONTEXT

Logging Service 讓系統行為變得可觀察。

通訊事件發生後，診斷資料需要被保留下來，工程師才能還原狀態與時序。下圖是通用設計，用來建立閱讀程式的問題清單，不代表公司實作。

事件產生→Filter / 編碼→Buffer→傳輸 / 儲存→Decoder

先學會問這四個問題

  • 資料由誰產生、誰消費？
  • 交出去的是副本，還是 pointer？
  • Buffer 滿了，會等待還是丟棄？
  • 格式與解碼資料的版本一致嗎？

公開實作：Zephyr Logging

它展示 frontend/backend、filter、非同步處理與 dictionary-based logging。後者使用與 build 對應的資料字典解碼，可用來理解版本為何重要。[3]

「沒有 log」不只有一種原因。

依序檢查：事件未發生 → 被 filter 擋下 → buffer 丟棄 → 傳輸失敗 → 檔案未寫入 → 無法解碼 → 顯示條件排除。每一步都要找計數、狀態或錯誤碼作為證據。

Android radio log ≠ 完整 Modem trace。 adb logcat -b radio 讀取 Android 的 radio／telephony buffer；它不是所有 firmware binary log 的替代品。[5]
ICD、MDM、MTF、DHL：在公司內部怎麼對照？

目前沒有足夠可靠的公開來源確認本專案情境中的定義；不猜全名或模組關係。請在公司內部釐清各項的類型、執行位置、輸入／輸出、buffer ownership、初始化流程與常見失敗情境。

這個公開知識庫只整理共通知識，不收錄內部 code、log 或未公開的架構對照。

06 / POCKET GLOSSARY

遇到縮寫，先回來這裡。

UE

User Equipment；使用者終端，例如手機。

AP

Application Processor；典型手機中執行應用與作業系統的處理端。

Modem

負責蜂巢式通訊協定與基頻相關處理，與 RF 硬體協作。

RAN

Radio Access Network；無線接取網路。

gNB / eNB

分別是 5G NR 與 LTE 的基地台節點名稱。

5GC / EPC

分別是 5G 與 LTE 系統的核心網路架構。

RRC

Radio Resource Control；無線資源與連線控制。

NAS

Non-Access Stratum；終端與核心網路間的控制協定。

PDU session

5G 中終端與資料網路之間的資料連線關聯。

Buffer

暫存資料的記憶體空間；容量與滿載策略會影響 log 是否丟失。

Dictionary

解碼資料的對照資訊；是否需與特定 build 綁定依系統設計而定。

Firmware

裝置或子系統上執行的韌體；Modem firmware 不等於 Android App。

07 / CHECK YOUR UNDERSTANDING

能解釋，就可以繼續往下走。

先自己回答，再展開參考答案。你不必記住每個縮寫的完整英文。

01　AP 和 Modem 是什麼關係？

典型手機中，AP 執行應用與作業系統，Modem 處理蜂巢式通訊；兩者透過平台介面協作。邏輯職責不同，不表示一定是兩顆獨立晶片。

02　註冊成功，就代表 App 一定能上網嗎？

不一定。還需有可用資料連線，後續也可能遇到路由、DNS、TLS 或應用服務問題。應分層尋找證據。

03　為什麼拿到 binary log，仍可能看不懂？

可能缺少正確格式資訊或對應版本的 dictionary，也可能有資料截斷、未知 ID 或解析錯誤。先確認版本與資料完整性。

04　新增 log 後看不到，第一步要做什麼？

確認程式路徑是否真的執行，以及 log 是否被編譯進去、是否被 runtime filter 關閉，再沿 buffer、傳輸、儲存、解碼逐段檢查。
