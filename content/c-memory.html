01 / FROM MANAGED TO EXPLICIT

C 要你明確管理資料的邊界。

你可能習慣 Python 的物件、容器與垃圾回收。C 的 pointer 只提供存取物件的方式；它本身不帶 buffer 長度，也不會自動延長物件的生命週期。先練習替每個參數說清楚「指向什麼、有幾個元素、誰擁有、何時失效」。

閱讀程式時的線索你應該確認的事
uint8_t *data, size_t lendata 是否指向至少 len 個有效元素？能否修改？
const uint8_t *data不能透過這個 pointer 修改資料；不代表其他人無法修改。
malloc / free配置是否成功？所有路徑是否釋放？是否還有人持有 alias？
return bufferbuffer 的生命週期是否超過這次函式呼叫？

語言規則查核：C11 committee draft N1570 §6.2.4、§6.3.2.1、§6.7.3、§7.22.3。[C]

02 / COMPILE & LINK

先看懂一個 C 專案如何變成程式。

預處理器處理 #include 與條件編譯；編譯器分析各 translation unit；linker 把 object files 與需要的程式庫連起來。實作可能合併步驟，但這個模型有助於分辨錯誤來源。

.c + headers→預處理 / 編譯→.o→連結→可執行檔

.h 通常放型別與函式宣告；.c 放定義。Header guard 避免同一 translation unit 重複包含；它不能解決跨檔案的重複定義。

編譯錯誤

先查型別、宣告、語法與 include 路徑。不要一開始就刪 warning。

連結錯誤

Undefined symbol 可能是缺少定義、漏編某個檔案或漏連程式庫；宣告存在不代表實作已被連入。

本教材使用 C11 與 host 端 Clang。公司 firmware 的工具鏈、編譯旗標與 ABI 另依專案確認。[B]

03 / POINTER + LENGTH

陣列不是 pointer，傳參時卻容易混淆。

uint8_t data[4] 是四個元素的陣列；uint8_t *p 是 pointer。陣列表達式在多數情況會轉成指向首元素的 pointer，但 sizeof data 等情況是例外。函式參數寫成 uint8_t data[] 仍會調整成 pointer 參數。[C]

uint8_t bytes[] = {0x41, 0x00, 0x42, 0xff};
size_t length = sizeof bytes;  /* 此處是真正的陣列 */
inspect(bytes, length);        /* 長度要另外傳 */

/* 函式內 sizeof data 是 pointer 大小，不是 buffer 長度 */
void inspect(const uint8_t *data, size_t length);
Binary payload 不一定是字串。上面包含 NUL（0x00），但仍有四個 bytes。strlen 找的是字串終止符，不是 binary 長度；用 %s 讀沒有終止符的 buffer 可能越界。

Pointer arithmetic 必須留在對應陣列範圍或其 one-past 位置；one-past 可用於邊界比較，但不可解參考。不要以「這個位址看起來有效」取代物件邊界。[C]

04 / OWNERSHIP & LIFETIME

非同步 logging 最容易踩到生命週期。

自動儲存期的區域物件通常放在 stack；動態配置的物件通常稱為 heap。這些是常見實作術語，C 語言規則重點是 storage duration，而不是強制指定一種硬體配置方式。

/* 錯誤示意：離開函式後，local 的生命週期結束 */
const char *bad_message(void) {
    char local[] = "ready";
    return local;
}

Logger 若只把 pointer 入列，呼叫端離開後才讀取資料，就可能取得已失效的內容。可行設計包含同步複製、移轉 heap／pool buffer ownership，或在消費完成前保證原物件存活。是哪一種必須由 API 契約決定。

策略需要付出的成本與約束
入列時複製 payload多一次 copy；必須限制大小與配置失敗處理。
傳遞 pointer，移轉 ownershipProducer 不再重用；consumer 完成後歸還或釋放。
借用穩定資料必須確保所有非同步讀取結束前，資料仍有效且無不當並行修改。

free(p); p = NULL; 只修改 p 這個變數；其他 alias 仍可能懸空。memcpy 要求來源與目的範圍有效且不重疊；可能重疊時使用 memmove。[C]

05 / BYTES ARE A CONTRACT

記憶體中的 struct，不等於 wire format。

Struct 可能含有 padding；成員對齊、整數大小與 byte order 也可能因實作而異。直接把接收 buffer cast 成 struct pointer，還可能違反 alignment 與 effective type 規則。使用 packed extension 也不會自動解決 byte order 或跨平台格式問題。[C]

教學協定使用 8-bit byte 與 little-endian。以明確位移組合整數，並在讀欄位前檢查長度。uint8_t 等精確寬度型別只在實作支援時提供；範例用 static assertion 明確要求 CHAR_BIT == 8。

/* 前置條件：p 至少有 4 個可讀 bytes */
static uint32_t le32(const uint8_t *p) {
    return (uint32_t)p[0] | ((uint32_t)p[1] << 8) |
           ((uint32_t)p[2] << 16) | ((uint32_t)p[3] << 24);
}

位移前先轉成足夠寬的 unsigned 型別，避免 promotion 後的 signed 位移問題。Signed overflow 是未定義行為；unsigned 運算依型別寬度取模，但 wraparound 仍可能造成長度計算漏洞。

/* 先檢查 header，再用減法避免 header + length 溢位 */
if (n < HEADER) return NEED_MORE;
if (length > MAX_PAYLOAD) return INVALID;
if (length > n - HEADER) return NEED_MORE;

查核章節：N1570 §6.2.6.1、§6.3.2.3、§6.5、§6.5.7、§6.7.2.1、§7.20.1.1。[C]

06 / WHEN TASKS SHARE DATA

Volatile 不是鎖，也不是 ownership。

多個 thread 同時存取非 atomic 物件，其中至少一方寫入，而且沒有必要的同步，可能形成 data race。volatile 不提供一般 thread synchronization，也不能用來保證其他記憶體的發布順序。[V]

Task / thread context

從平台提供的 mutex、queue 或其他同步原語開始。不要用「變數很小」推論存取一定安全。

Interrupt context

中斷處理的可用 API 依 RTOS 與 port 規則而定。FreeRTOS 提供 FromISR 類 API；不可直接把 task 的阻塞流程搬進 ISR。

FreeRTOS queue 複製的是設定好的 item bytes；若 item 是 pointer，被複製的只是 pointer 值，不是它指向的 payload。這仍需要生命週期設計。[R]

目前先掌握契約。這個知識庫的 ring buffer 範例是單執行緒模型，不能直接當作 lock-free firmware 程式使用。
07 / BUILD SOMETHING SMALL

實作：看見 copy 與 alias 的差異。

下載 memory_demo.c，或在 repo 根目錄執行下列命令。需要已安裝的 Clang；不需要 Modem 硬體。

mkdir -p build
clang -std=c11 -Wall -Wextra -Wpedantic -g -O1 \
  -fsanitize=address,undefined -fno-omit-frame-pointer \
  examples/memory_demo.c -o build/memory_demo
./build/memory_demo

第一列 bytes 為 43 00 42 ff，第二列為 41 00 42 ff。Pointer size 取決於 host ABI，不要硬背成 8。這說明複製後的資料不會隨原陣列修改而一起改變。

練習 1：把 copy 換成指向 original 的 pointer，會如何？

兩者會指向同一個陣列，看到相同的更新；此時不可 free 那個 pointer，因為它不是動態配置的物件。

練習 2：為什麼不直接把 sizeof(data) 當成長度？

函式收到的是 pointer；sizeof 計算 pointer 型別的大小。它不含 caller 的陣列容量資訊。

練習 3：如果 logging 延後才讀取 copy，要何時 free？

要等所有需要讀取它的 consumer 都完成，並由明確的 owner 釋放。函式回傳不一定代表非同步消費已完成。

Sanitizer 是輔助，不是安全證明。ASan 檢查部分記憶體錯誤，UBSan 檢查部分未定義行為；沒有被執行到的錯誤路徑仍可能存在。[A] [U]
